# OpenJWC 服务管理、TUI 与 Agent 检索体验改进

## 已确认的边界

- 服务统一由 systemd 托管，默认用户级；不实现自建守护进程或 PID 文件杀进程方案。
- linger 显式检查，系统级部署需要明确授权，不静默提权。
- 旧 `/api/v1/client/notices/search` 保留快速词法检索；`similarity_score`（旧响应实际字段名，另保留 `distance`）明确为弃用的兼容占位，不是语义分数，`min_similarity` 不再具备旧向量阈值语义。
- 自然语言检索通过 chat Agent 完成，不新增独立搜索接口，不引入向量数据库或 embedding。
- 保留客户端旧 chat 协议；新增 chat 事件流协议以支持客户端显示工具调用。
- 不修改真实旧数据库，不实际安装、卸载或停止本机已有服务，不提交 Git。现有已暂存修改保持原状，不通过 reset 或重新暂存覆盖用户状态。

## 1. CLI 与 systemd 生命周期

命令：

```text
openjwc                       打开本地管理 TUI
openjwc serve                 前台运行，供 systemd 与调试使用
openjwc start                 启动已安装服务，并等待就绪
openjwc stop                  优雅停止，等待服务结束
openjwc restart               重启并等待就绪
openjwc status [--json]        查询部署、运行与就绪状态
openjwc service install       安装并启用用户级服务
openjwc service install --now  安装、启用并立即启动
openjwc service uninstall     停止、禁用并移除本项目管理的服务配置
openjwc recover               服务停止后执行离线恢复
```

- 生命周期命令支持显式 `--user` / `--system`，默认用户级，不隐式切换服务身份或数据目录。
- 未安装时 `start` 给出安装命令，不偷偷创建部署；检查 systemd、用户管理器、linger 与配置路径。
- 用户级配置写入私有配置目录，unit 放入用户 systemd 目录；记录绝对二进制路径与明确的启动配置，不能依赖 SSH 会话环境变量自动传入 systemd。
- 系统级部署采用固定服务身份与显式数据目录；权限不足给出具体命令，不由后台 RPC 请求触发 sudo。
- 使用标准库 `os/exec` 调用封闭参数的 systemctl/loginctl，禁止 shell 拼接；正确处理 unit 路径、空格、引号与 `%` 转义。
- `status` 区分未安装、停止、启动中、运行但未就绪、正常及失败；结合 systemd 状态与有界本地 RPC 探测，不以 PID 或 socket 文件存在当作健康。
- 未开启 linger 时明确说明 SSH 退出后的限制与授权操作，不宣称已经具备持久常驻能力。
- 安装/卸载可重复执行，只管理可辨识的 OpenJWC unit/config；外来或被人工改动的冲突文件不得静默覆盖。卸载保留数据库、备份和用户配置，不提供默认清数据行为。
- TUI 的服务管理是本地 CLI 能力，不走需要服务存活的 RPC；服务停止时仍可进入服务管理页面。系统级提权留给显式 CLI 操作。

## 2. Bubbles TUI、可靠分页与 Vim 键位

- 审查 Bubbles 与现有 Bubble Tea v1 的兼容版本、许可证、维护情况及间接依赖后再加入。标准库没有终端表格、文本编辑及 viewport 组件，复用现有生态而不是继续手写这些行为。
- 列表改用 table，详情改用 viewport，单行/多行表单使用对应输入组件，键位通过 key/help 统一定义。
- 按终端显示宽度计算列宽，处理中文、emoji、长字段和窗口缩放；窄屏裁剪/隐藏低优先级列，完整字段通过详情查看。
- 管理响应增加明确的分页元数据；分页查询在同一读快照取得总数和当前页，排序增加唯一键兜底。非分页页面明确标记不可翻页。
- `[` / `]` 到边界不发送请求；只有一页及零记录时禁止翻页；删除导致末页失效时回退到有效页；刷新失败不破坏原列表和选择状态。
- 默认普通模式支持 `h/j/k/l`、`gg/G`、`Ctrl+d/u`、`/` 当前页过滤、`?` 帮助；过滤范围明确标为当前页，不伪称全库搜索。
- 输入字段使用插入模式，Esc 返回普通模式，再 Esc 取消表单；普通模式中导航键不能输入文本或触发破坏性操作。
- 重新分配与 Vim 导航冲突的业务键位；所有破坏性动作继续显式确认。键盘帮助随页面和模式变化。

## 3. Unix 风格帮助与退出展示

- 使用明确的命令解析和退出码，支持 `-h`、`--help`、子命令帮助及 `--version`；帮助不要求配置、数据库或服务可用。
- 帮助成功写 stdout，参数错误写 stderr；文档说明业务状态命令的退出码。
- 交互终端帮助输出 OpenJWC 字标（按后续用户反馈，从 ASCII 线条改为类似 OpenCode 退出展示的独立 Unicode 块状点阵，并用于退出摘要）；窄终端降级，重定向时无装饰或控制码，支持禁用 banner，颜色遵守 NO_COLOR。
- TUI 退出后恢复光标、屏幕和终端模式，再输出简洁品牌与会话摘要，不复制其他产品图案、不回显密钥。
- 服务运行状态来自检查；离线、恢复模式和失败退出分别说明，不固定打印“服务继续运行”。

## 4. Agent 事件协议与旧 chat 适配

- Agent 内核增加有界、可取消的类型化事件输出；旧 `Answer` 作为只收集最终答案的适配器保留。
- 新增 `POST /api/v2/client/chat`，使用标准 SSE + JSON。事件至少包括运行开始、工具开始/结束、答案片段、完成和失败；定义协议版本、run ID、递增序号、工具调用 ID 与终止规则。
- 工具事件只提供校验后的工具名、受限参数摘要、状态、耗时与引用摘要；不暴露隐藏思考、系统提示词、认证材料或无界工具正文。
- 旧 `/api/v1/client/chat` 继续保留 JSON 回复与旧 raw-text SSE 适配，不混入工具事件；两个入口共享身份、当前权限、并发容量和推理预算。
- 实现模型流式响应的增量解析与工具参数组装；仅将最终答案阶段的可展示文本作为 answer.delta，不把模型的中间工具轮内容当成最终答案。无法提供增量时允许明确的单片段答案，不伪装为逐 token 流式。
- 测试断连取消、慢消费者、错误终止、工具超限、跨用户隔离以及旧客户端帧格式；同步 OpenAPI 和客户端消费示例。协议交付不等于现有 Android/机器人前端已经适配工具卡片。

## 5. VFS 分类视图与时效性

- 保留 `/notices/<编码ID>.md` 稳定文件身份，不因分类或日期变化破坏引用。
- 增加根目录说明、按类别、按日期和近期资讯的虚拟目录视图；这些只是 SQLite 查询投影，不导出宿主文件、不复制资讯实体。
- 提供受限的类别与日期范围过滤、分页及排序选择；工具保持只读，不开启真实 shell、文件系统或网络权限。
- 列表结果包含 ID、标题、类别、发布日期和可读取的规范路径；正文携带官方链接与附件链接，长正文支持有界续读，避免永远只能看到前半段。
- 给 Agent 注入明确的当前日期/时区、数据范围及最近成功抓取时间；默认近期优先，未命中可以扩大范围，用户指定历史日期时尊重其范围。
- 区分发布时间、抓取时间与业务截止时间；仅从已读取证据引用截止日期，不把新发布自动等同于仍有效或最高权威。
- 为旧独立搜索明确标识词法模式并记录分数字段弃用说明，保持旧 JSON 形状，不将占位值描述为置信度。

## 6. 爬虫集成与进度

- 保留进程内 Go 实现、学校站点白名单、幂等写入和单任务限制，不添加外部爬虫运行时。
- 新增可查询的任务状态与按来源的最近成功/失败摘要，区分扫描、保存、跳过和失败数量。
- 手动爬取使用启动任务并查询进度的方式，任务由后台服务拥有，不因关闭 TUI 就被意外取消；显式取消和服务退出能够结束任务。
- 调度与手动入口共享任务闸门，统一更新成功时间，避免状态彼此脱节；处理当前手动 RPC 超时短于任务预算的问题。
- 增补多页、旧置顶条目、解析结构失效、日期边界、重复 URL、附件及部分失败的夹具；真实网站访问若未完成则如实列为未验证。

## 验证与交付

1. 缺陷修复先增加复现测试：中文列边界、单页翻页、末页回退、Vim 键位冲突。
2. systemd 操作用可注入命令执行器和临时目录测试；覆盖不存在管理器、权限错误、linger、配置冲突、重复安装卸载、启动失败和数据保留。
3. `systemd-analyze verify` 可用时检查生成 unit；真实 install/start/stop/uninstall 只在获得授权的测试环境执行，不更改当前主机已有部署。
4. 新旧 chat 契约测试、事件顺序/取消/限流测试、VFS 筛选与时间排序测试、爬虫任务生命周期测试。
5. 执行 gofmt、go vet、go test、go test -race、静态构建与真实 PTY 冒烟；检查 diff，不改迁移历史、不泄露数据和凭据。
6. 更新 README、部署/迁移/架构/验证文档、OpenAPI 和许可证清单。记录无法验证的真实模型、站点及 systemd 环境条件，不宣称生产验收完成。

## 实施顺序

先落地 CLI/systemd 与状态边界，再处理分页和 Bubbles/Vim/帮助展示，随后实现 Agent 事件与 VFS 时间分类，最后完善爬虫任务管理和整体回归。按职责拆分文件，保持中文声明注释和手写 Go 文件不超过 300 行，不进行无关重构。

## 实施补充

- 模型侧已实现 SSE 增量解析和分片工具参数组装；对外工具进度实时发送。由于工具调用可能在同一模型轮次的 content 之后出现，为避免把工具轮中间正文当答案暴露，当前答案在确认最终轮结束后整体发送，事件显式标记 `delivery=buffered-final`。这不是逐 token UI，后续若需要真正逐 token 应增加明确禁止工具的答案生成阶段，而不能猜测片段属于最终答案。
- 月份目录由实际数据覆盖范围生成，某个月份可以为空；分类目录是单一 label 的视图，不改变现有资讯身份或引入多标签模型。
- 爬虫任务本身不支持进程重启后自动续跑；来源进度持久化，遗留 running 状态在启动时标记中断。TUI 使用显式刷新查询进度。
- 系统级 TUI 的本地变更入口保持禁止提权；需要变更时使用显式 CLI。部署前需要创建服务账号并将可执行文件安装到系统账号可访问的稳定系统路径。
