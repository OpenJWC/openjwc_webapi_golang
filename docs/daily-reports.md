# 日报接口

日报由服务端定时生成，客户端通过只读接口获取已完成内容。日报接口只返回 `completed` 状态，生成中或失败的内容不会对外暴露。

## 权限

两个接口都需要当前用户具备浏览资讯权限（`browse`），并通过 Bearer Token 与登录设备认证。

## 按日期获取

```http
GET /api/v2/client/daily-reports/{date}
Authorization: Bearer <token>
X-Device-ID: <登录设备ID>
```

- `date` 格式固定为 `YYYY-MM-DD`，例如 `2026-09-14`。
- 只返回该日期已完成的日报。
- 该日期尚未生成或仍失败时返回 `404`，正文为 `{"detail":"该日期日报尚未发布"}`。

成功响应：

```json
{
  "msg": "获取成功",
  "data": {
    "date": "2026-09-14",
    "content": "日报正文"
  }
}
```

## 获取最近日报

```http
GET /api/v2/client/daily-reports/today
Authorization: Bearer <token>
X-Device-ID: <登录设备ID>
```

- 由**服务器**按本地时区（系统设置 `timezone`，默认 `Asia/Shanghai`）解析当天日期，返回**最近一份日期不超过今天的已完成日报**。
- 客户端无需自己计算日期，避免客户端时钟与服务器不一致时取错日期。
- 尚无任何已完成日报时返回 `404`，正文为 `{"detail":"尚无已发布日报"}`。

成功响应与按日期接口相同，`data.date` 表示实际返回的日报日期（通常是前一天，也可能是今天）。

## 生成语义

- 日报由 `daily_enabled` 与 `daily_time` 控制；默认每天 `00:10`（本地时区）生成**前一日**的日报。
- 因此正常情况下，`today` 接口返回的是**昨天**的日报。
- 生成失败不会发布半成品；管理员可在本地 TUI 手动按日期重试生成。

## 移动端消费建议

- 首页展示用 `today` 接口，避免客户端计算日期。
- 历史回看用按日期接口，逐日查询。
- `404` 表示该日期/目前没有可展示日报，应显示“暂无日报”，而不是报错。
- 正文为不可信文本，按纯文本或受控 Markdown 渲染，不做脚本执行。
