## 并发基准

开发机：Linux amd64，Intel i7-1185G7，8 个逻辑执行线程；当前工具链 `go1.27.1-X:nodwarf5`，模块最低版本仍为 `1.26.5`。

`make bench` 的一次结果：

```text
BenchmarkNoticePagesParallel-8    9490    128206 ns/op    39656 B/op    772 allocs/op
```

工作负载是临时 SQLite 中 1000 条小资讯、每次读取 20 条、并发执行。`ns/op` 是基准总时间除操作次数，**不是单请求 P95 延迟**，也不是外部 HTTP QPS。结果只证明该夹具下的表现，不能替代目标服务器上的持续压测。

资源保护：

- 最多 128 个在途客户端请求，超限返回 503。
- 四个并发密码运算槽；登录/注册每直接来源 IP 突发 20、每秒补充 2，地址表最多 4096 条。
- 八条只读 SQLite 连接、一条写连接；写忙等待最长五秒。
- 全局四个 Agent，同一用户最多一个聊天；每次两分钟、八轮、十六工具调用。
- 请求体 1 MiB、请求头 16 KiB；模型响应 2 MiB，爬虫响应 4 MiB。
- 爬虫单任务、串行来源请求；日报单任务，受全局 Agent 容量约束。

## 尚未验证或有意限制

- 没有配置或调用真实收费模型；各 OpenAI 兼容供应商的工具协议差异仍需真实凭据验收。
- 未执行学校站点全量生产爬取，也未证明其当前 HTML、限流策略或全部历史附件均兼容；已核对官方配置并使用离线夹具。
- 未在目标生产机器进行网络吞吐、P95/P99、长时间写入压力、磁盘耗尽、掉电及硬件故障测试。一至两个字符的子串搜索可能扫描大量正文，是大数据规模的重点压测项。
- 未实际安装 systemd 单元或配置生产 TLS 证书；它们是部署样例和代码路径，不能视为已部署。
- 未执行漏洞数据库扫描；许可证检查和 `go vet` 不等于 `govulncheck`。
- 当前日报最多处理 100 篇，超过上下文预算会失败且不发布；自动补偿限前一日，其他日期手工生成。
- 模型事实准确性与摘要质量不能由单元测试保证；重要教务事项须核对原始资讯。
- 所有历史分支和非法请求并未做逐字段 Python/Go 差分测试；协议差异见 [migration.md](migration.md)。

## 爬虫故障、外部协议与本地 Chat（2026-09-14）

- 使用临时数据库和 `127.0.0.1:0` 实际派发单页、30 天 JWC 任务复现：调度器正常接纳并运行，但最终扫描 154、保存 38、跳过 97、失败 19。SHA-256 反查确认重复正文错误 ID `860b...` 是 `/zxdt/list.htm`，根因是宽泛 `tr` 选择器把包含整张列表的外层布局行当作资讯；另有 HTTPS `.htm` 返回 301 到同主机 HTTP `.psp`，旧策略拒绝全部重定向。CS 与新生学院相同条件分别 completed，排除任务派发器故障。
- JWC 选择器改为至少含两个直接 `td.main` 的行；只允许编译期官方同主机的有限重定向，并把 HTTP 降级改回 HTTPS。部分 JWC 详情会返回“仅校内地址访问”页面：现在计入来源 `failed` 数及说明，但不再把已完整扫描列表且保存其他资讯的整项任务伪装为失败；列表抓取、整体结构或数据库写入失败仍使来源失败。
- 修订后真实临时抓取 JWC 每栏目第一页完成：扫描 140、保存 38、跳过 89、不可访问详情 13，来源状态 completed 且明示部分详情；结果随站点当时内容变化，不是固定性能基准。
- 新增外部进程 NDJSON v1。测试覆盖多个配置的绝对路径/重名/未知字段，严格事件、进度回退、资讯领域校验、缺失终止、进程组取消、任意来源迁移和 systemd 环境持久化。真实临时服务串行运行内置 CS 和 `/tmp/openjwc-crawlmock`，两个来源 completed，外部测试资讯成功导入；未安装或运行不受信任的真实第三方爬虫。
- 新增 loopback HTTP 模型例外和标准库 `tools/chatmock`。临时数据库完整执行注册、审核、权限、登录、两轮模型 SSE、`ls /recent` VFS 工具调用和 `/api/v2/client/chat`，事件顺序为 run.started、tool.started、tool.completed、answer.delta、run.completed。没有调用真实模型或使用真实凭据。
